# 物理刷题 · 高中选择题

给高中物理老师做的刷题工具。纯静态网页（PWA），**不需要服务器、不需要数据库、不需要构建工具**，用 iPhone 的 Safari 打开后「添加到主屏幕」，就是一个全屏 App，断网也能刷。

---

## 一、它有什么

| 功能 | 说明 |
| --- | --- |
| 随机组卷 | 自选知识点（力学／电磁学／热学／光学／近代物理）、题型（单选／多选）、题量，随机抽题；可勾选「只抽没做过的题」「打乱选项顺序」 |
| 按知识点练习 | 按五个知识点顺序刷，适合系统梳理；每类显示历史正确率 |
| 错题本 | 答错或选不全的题自动收录，**再次答对自动移出**，也可手动移出 |
| 收藏夹 | 讲评时看到好题点一下收藏，之后集中重做 |
| 即时解析 | 提交后立刻给判定 + 正确答案 + 逐步解析 + 易错点说明 |
| 高考评分规则 | 多选题：全对满分，选对但不全得半分，有错选得零分（可在设置里关掉半分） |
| 统计 | 总体正确率、各知识点掌握情况（用颜色区分 80% / 60% 两档） |
| 题库导入导出 | 可以直接粘贴试卷纯文本自动识别成题目，也可以导入 JSON；可导出题库和练习记录做备份 |
| 深色模式 / 字号调节 | 跟随系统或手动切换；字号 90%–130% 可调 |
| 离线 | 通过 https 打开过一次后，页面和题库都会缓存到本机 |

放进去的每道题都带**答案、解析、知识点标签、难度、来源类型**。

## 二、先在本机看一眼（可选）

需要装 Node.js（18 以上）。在项目目录里执行：

```bash
npm run serve
```

终端会打印两个地址，电脑用 `http://localhost:5173`，手机用同一 WiFi 下的 `http://192.168.x.x:5173`。
（手机用局域网 IP 打开时没有离线缓存，因为 Service Worker 只在 https 或 localhost 生效。正式用请走下面的部署。）

如果改过 `data/bank-*.json`，先重新生成题库：

```bash
npm run bank
```

它除了生成题库文件，还会做这些检查并打印报告：id 是否重复、答案是否都在选项里、多选题答案个数是否合理、解析是否过短、是否残留 LaTeX 语法、题干是否重复、**声称真题却给不出年份**、各知识点单选答案字母是否分布不均。

还可以跑一次端到端自测（模拟真实点击走完答题流程，需要 `jsdom`，没有会自动跳过）：

```bash
npm test
```

## 三、部署到公网（推荐，做完这一步手机随时能打开）

### 方案 A：Vercel（最快，约 3 分钟，自动 https）

1. 打开 <https://vercel.com/signup>，用邮箱或 GitHub 账号注册（免费额度对个人使用完全够）。
2. 打开 <https://vercel.com/new>。
3. 把**整个 `physics-quiz` 文件夹拖进页面的上传区域**（不需要 Git、不需要命令行）。
4. 部署类型如果让你选，选 **Other**；Build Command、Output Directory 都**留空**。
5. 点 **Deploy**，等十几秒，会得到一个 `https://xxxx.vercel.app` 的网址。
6. 这个网址就是你的题库地址。免费额度对个人使用完全够；万一平台把长期不访问的项目暂停了，重新 Deploy 一次就恢复。

> 提示：以后想换题，重新拖一次文件夹上传即可，网址不变（在同一个项目里 Deploy 新版本）。

### 方案 B：GitHub Pages（完全免费、无流量限制，稍麻烦一点）

1. 注册 <https://github.com>，新建一个仓库（Repository），名字比如 `physics-quiz`，选 **Public**。
2. 进入仓库 → **Add file → Upload files**，把 `physics-quiz` 里的**所有文件和文件夹**拖进去，Commit。
3. 仓库 → **Settings → Pages** → Source 选 **Deploy from a branch**，Branch 选 **main**、目录选 **/(root)**，Save。
4. 等 1–2 分钟，页面顶部会出现网址：`https://你的用户名.github.io/physics-quiz/`。

> 本项目的所有路径都是相对路径，放在 `physics-quiz/` 这样的子目录下也能正常工作。
> 目录里有个 `.nojekyll`（浏览器上传时可能不会带上隐藏文件），**没传上去也没关系**——本项目没有以下划线开头的文件，不依赖它。

#### 打开是 404 "File not found"？按顺序试这 5 条

出现 GitHub 那个灰色 404 页，说明 Pages 已经在提供服务了，**只是你访问的那个路径下没有 `index.html`**。按可能性从高到低：

1. **网址末尾少了仓库名**。正确形式是 `https://用户名.github.io/仓库名/`。
   如果你建了仓库 `physics-quiz`，只打开 `https://用户名.github.io/` 就是 404。
   网址里的**大小写也要和仓库名一致**（`Physics-Quiz` ≠ `physics-quiz`）。
2. **上传时多套了一层文件夹**。这是最常见的原因：把 `physics-quiz` 这个文件夹整个拖进去了，
   于是仓库根目录下是 `physics-quiz/`，`index.html` 在第二层，根路径自然没有首页。
   - 先花 10 秒验证：把网址改成 `https://用户名.github.io/仓库名/physics-quiz/` 试一下，能打开就是这个原因。
   - 根治：在仓库里点进 `physics-quiz` 文件夹，选 **Add file → Upload files** 把里面的文件**重新传到仓库根目录**，
     或者用下面的「用 Git 上传（不会出现嵌套）」。
3. **Pages 的 Source 选成了 "GitHub Actions"**。本项目是纯静态文件，不需要 Actions。
   改成 **Deploy from a branch** → Branch 选 **main**、目录选 **/(root)** → Save。
4. **分支或目录选错**：分支选了 `master` 但文件在 `main`，或者目录选了 `/docs`。回到 Settings → Pages 核对。
5. **刚点完 Save，还在构建**。等 1–5 分钟刷新；在仓库的 **Actions** 标签页能看到进度。

#### 用 Git 上传（不会出现嵌套，一次配好永久省心）

如果电脑上装了 [GitHub Desktop](https://desktop.github.com/)，这是最不容易出错的方式：

1. 打开 GitHub Desktop → **File → Add local repository** → 选择 `physics-quiz` 这个文件夹。
   如果提示 "not a Git repository"，点 **create a repository**，然后点 **Publish repository**（Public 不要勾 Keep this code private）。
2. 以后改完题，在 GitHub Desktop 里填一句说明 → **Commit to main** → **Push origin**，等 1 分钟网站就更新了。

### 方案 C：只在电脑上跑（不想联网）

保持 `npm run serve` 运行，手机连同一个 WiFi 访问局域网地址。缺点是电脑关机就用不了。

## 五、加题（题库现在是空的，从这里开始）

先弄明白一件事：**题目放在哪里，谁能看到，完全不同。**

| 放哪 | 谁看得到 | 适合 |
| --- | --- | --- |
| 在 App 的「题库管理」里导入 | **只有你这台手机** | 自己备课、临时试几道题 |
| 写进 `data/bank-*.json` 再跑 `npm run bank`，然后重新部署 | **所有打开网址的学生** | 正式给学生用（推荐） |

所以打算给学生刷题的话，请走下面的**方式三**；只是自己先看看效果，方式一最快。

### 方式一：在手机上直接粘贴试卷文本（最快，但只存在本机）

打开 App → 底部 **我的 → 题库管理** → 把题目文本粘进文本框 → 点 **「导入粘贴内容」**。

从**组卷网、Word 试卷、PDF 复制出来的文字**基本可以直接用，只要能保持这种常见格式：

```
1. 一物体从静止开始做匀加速直线运动，2 s 末速度达到 4 m/s，则它的加速度为
A．1 m/s²
B．2 m/s²
C．3 m/s²
D．4 m/s²
【答案】B
【解析】由 v = v₀ + at 得 a = v/t = 4/2 m/s² = 2 m/s²。
```

程序会自动识别出题干、四个选项、`【答案】` 和 `【解析】`，并且：

- 支持 `A．` `A.` `A、` `A)` 等各种选项标点；
- 支持 `【答案】BD`、`答案：BD`、`答案 B`；
- 自动按关键词**猜测知识点**（力学／电磁学／热学／光学／近代物理）；
- 题目 id 由**题干内容**生成，所以同一份文本反复粘贴不会变成重复题，粘贴新题也不会覆盖旧题；
- 每题都必须带答案，**没有答案的题会被跳过**并列出题号提醒你补上。

需要提醒的两点：知识点是猜的，导入后扫一眼有没有归错类；答案和解析的准确性请自己核对。

### 方式二：粘贴 / 导入 JSON（同样只存在本机）

- 点 **「下载空白录入模板」** 拿到格式示例；
- 把题目写成 JSON 数组，粘贴进文本框点 **「导入粘贴内容」**，或直接把 `.json` 文件选中导入。

题目字段：

```json
{
  "id": "MY-001",
  "topic": "力学",
  "tags": ["动能定理"],
  "type": "single",
  "stem": "题干文字",
  "options": [
    { "key": "A", "text": "选项 A" },
    { "key": "B", "text": "选项 B" },
    { "key": "C", "text": "选项 C" },
    { "key": "D", "text": "选项 D" }
  ],
  "answer": ["B"],
  "explanation": "解析：正确思路 + 其余选项为什么错",
  "source": "2023 年××卷·改编",
  "sourceType": "真题改编",
  "difficulty": 3
}
```

宽松之处（导入时会自动兼容）：

- `type` 可写 `single` / `multiple`，也可不写（由答案个数自动判断）；
- `answer` 可写 `"B"`、`"BC"`、`["B","C"]`；
- `options` 可写字符串数组 `["甲","乙","丙","丁"]`，也可写 `[{key,text}]`；
- `topic` 建议用五个标准知识点之一（力学／电磁学／热学／光学／近代物理），这样会自动归入对应分类；写别的值也不会报错，会单独成一类；
- 缺 `id` 会自动按**题干内容**生成（所以同一道题反复导入不会变成两条）；`explanation`、`source` 缺失会被提示但不会阻断导入；`sourceType` 不写就是「未标注」。

**格式限制：不要用 LaTeX。** 手机端不做公式渲染，请直接写 Unicode 字符，例如 `v₀`、`m/s²`、`ΔU`、`μ`、`θ`、`×10⁻¹⁹`、`√3`、`p₁V₁/T₁ = p₂V₂/T₂`。

**出题时最好遵守的两个习惯**（不是硬性要求，但能少踩坑）：

1. **解析里不要用 A/B/C/D 指代选项，直接写选项内容。** 写成「错项 7.5 m 是把 3 s 全当成运动时间」而不是「A 项 7.5 m 是……」。这样以后你调整选项顺序、或者用「打乱选项顺序」功能，解析都不会错位。
2. **注意答案不要集中在同一个字母。** `npm run bank` 会打印各知识点单选的答案字母分布，某个字母超过 45% 会提示「偏集中」——学生靠蒙一个字母就能得分，这一点在讲评时很明显。

### 方式三：写进题库文件（部署后所有学生都能看到，推荐）

这 5 个分卷文件现在都是空数组 `[]`，把题目按下面的结构写进去即可：

| 文件 | 放什么 |
| --- | --- |
| `data/bank-mechanics.json` | 力学 |
| `data/bank-em.json` | 电磁学 |
| `data/bank-thermal.json` | 热学 |
| `data/bank-optics.json` | 光学 |
| `data/bank-modern.json` | 近代物理 |

结构就是**一个 JSON 数组**，每个元素是一道题（字段见方式二）。例如 `bank-mechanics.json`：

```json
[
  {
    "id": "LX-001",
    "topic": "力学",
    "tags": ["匀变速直线运动"],
    "type": "single",
    "stem": "题干……",
    "options": [
      { "key": "A", "text": "……" },
      { "key": "B", "text": "……" },
      { "key": "C", "text": "……" },
      { "key": "D", "text": "……" }
    ],
    "answer": ["B"],
    "explanation": "解析……",
    "source": "来源说明",
    "sourceType": "真题",
    "difficulty": 3
  }
]
```

写完在项目目录里跑：

```bash
npm run bank
```

脚本会逐题校验（id 重复、答案不在选项里、多选答案不足两个、解析过短、残留 LaTeX、题干重复、**标了「真题」却没写年份**等），打印统计报告，并生成 `data/questions.js`（App 实际加载的文件）和 `data/questions.json`。**有硬性错误时会报错并停止，不会把坏数据写进去。**

然后重新部署一次（Vercel 拖文件夹，或 GitHub Desktop 提交推送），学生刷新就能看到新题。

> 想覆盖某道已有题目，用**相同的 `id`** 再写一条即可。

> 嫌手写 JSON 麻烦：把题目文本给我（或先在 App 里用「方式一」粘一次、导出 JSON），我可以批量转成分卷文件并跑完校验——这一步不需要你自己动手。

## 六、数据存在哪里

所有练习记录、错题本、收藏夹、自定义题库都保存在**你自己手机的浏览器本地**（localStorage），不上传任何服务器。因此：

- 换手机、换浏览器、清理 Safari 网站数据 → 记录会丢失；
- **重要题库请定期用「题库管理 → 导出」备份**；
- 想同步记录，可用「设置 → 导出练习记录」，在新设备上参考同一份题库导入。

> **iOS 的一个注意点**：Safari 对「长期不打开的网站」可能清理其本地存储（一般 7 天不用就会清）。**从主屏幕图标打开的 App 通常不受这条影响**，但为了保险，建议隔一段时间用「设置 → 导出练习记录」存一份到「文件」App 里；自定义题库也用「题库管理 → 导出」备份一份。

## 七、关于题目来源（请务必看一眼）

题目里有一个 `sourceType` 字段，用来标明这道题**到底是什么来路**，五种取值：

| 取值 | 含义 |
| --- | --- |
| `真题` | 能核对到年份、卷别、题号的原题 |
| `真题改编` | 有明确真题出处，并做过数据或情境改动 |
| `模拟题` | 按高考真题的模型与考法编拟，**不是原题** |
| `自编` | 依教材典型模型自行命题 |
| `未标注` | 从文本粘贴导入、还没写来源的题 |

**当前状态：内置题库已清空（0 题）。** 里面的题目全部由你自己导入，来源以你填写的 `sourceType` 为准。

一条建议留在这里，因为它关系到这个工具能不能放心用：

- **凡无法确认出处的题，一律不要标成「真题」**，也不要写具体的年份卷别。你可能在网上见过「2021 年全国乙卷第 18 题」这类精确标注，其中相当一部分是转述失真的——宁可标低，不冒充原题。
- 构建脚本 `tools/build-bank.mjs` 会替你守这条线：**标了「真题」或「真题改编」却写不出年份的，会直接提醒**。
- 无论来源如何，**正式用于考试、印发或对外发布前都请自行核对题目与解析**，尤其是需要计算的数值题。

顺带说明这个项目做过什么、没做什么：上一版（v1）那 100 道题是 AI 按高考模型编拟的，**没有照录任何一份原卷，`真题` 为 0 题**；当时答案键与解析经过一轮独立复核，查出并修正了 3 处答案键错误和若干解析错误，记录保留在 `VERIFICATION.md` 里，可作为后续命题的参考做法。那批题现已删除，仅存于项目外层的备份文件夹。

想补「往年高考真题」这个需求，正确路径是：**你提供能核实的原题文本**（组卷网、Word、PDF 复制均可），导入时把 `sourceType` 写成 `"真题"`、`source` 里写清「年份 + 卷别 + 题号」。来源由你自己核实，比 AI 转述可靠得多。

## 九、已知限制与可以继续加的功能

**限制**

- 只有选择题。计算题、实验题、图像题需要公式渲染和手写作答，是另一个量级的工作。
- 题干不能依赖图片。原卷里带图的题需要改写成文字描述才能入库。
- 记录只在本机，不做多设备云同步。
- 断网缓存需要先用 https 打开过一次；用局域网 IP 打开时无缓存。

**下一步可以加**（按性价比排序）

1. **题目变式 / 同类题推荐**：把同一 `tags` 的题串起来，错一道推同类三道。
2. **导出 Word / 打印版试卷**：按组卷结果生成可打印的排版。
3. **云同步**：接一个免费数据库（如 Supabase），让错题本跨设备同步。
4. **计算题与实验题**：引入 KaTeX 渲染公式 + 图片字段 + 学生手动输入答案。
5. **班级模式**：生成二维码，学生扫码进入指定题单，教师看整体正确率。
